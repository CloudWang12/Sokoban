# 关卡制作与交付操作规范

适用对象：关卡策划、技术策划、关卡验收人员。适用工具：UE 5.6 工程中的“推箱子关卡编辑器”；文档核对日期：2026-09-29。

本文规定从布局配置到试玩交付的操作流程。环境安装、输入绑定和 GameMode 接入细节见[工程配置与试玩接入规范](../Source/Sokoban/Sokoban/EditorSetup.md)。

## 1. 输入、产出与工具定位

制作输入包括关卡目标、预期解法、地图尺寸和难度意图。最终产出是 `USokobanLevelData` 类型的 DA（`.uasset`），以及对应的人工试玩结论。DA 保存初始布局，UE 地图负责提供运行世界，两者不是同一种资产。

工具使用“选中格子 → 设置地形／目标／占用物 → 应用到格子”的配置方式。它没有拖动绘制、画笔擦除或视口中拖放箱子 Actor 的操作；中间网格是布局界面，三维棋盘在 Play 时依据 DA 生成。

工作流程为：**新建／打开 → 调整尺寸 → 配置格子 → 校验 → 保存资产 → 指定试玩关卡 → 完成解法与异常操作验收 → 提交资源**。

## 2. 入口与界面

停止 Play，在 UE 顶部选择 **窗口 → 推箱子关卡编辑器**。若内容浏览器已经选中兼容的关卡 DA，新打开面板时会尝试载入它；也可以使用面板顶部资产选择框打开关卡。

| 区域 | 内容 |
|---|---|
| 顶部工具栏 | 新建关卡、资产选择、保存资产、撤销编辑、重做编辑、校验关卡 |
| 左侧 | 关卡 ID、关卡名称、内容修订号、宽高、调整尺寸、问题列表 |
| 中间 | 可滚动网格；选择格子查看并修改其配置 |
| 右侧 | 当前格子坐标、地形、目标点开关、占用物、应用到格子 |
| 底部 | 操作结果、错误与下一步提示 |

左上角为 `(0,0)`，X 向右，Y 向下。工具在 PIE 期间禁用；修改关卡前先停止游戏。

## 3. 数据填写约定

| 字段 | 含义与填写要求 |
|---|---|
| 关卡 ID / LevelId | 项目内唯一的逻辑标识；不同于文件名。建议使用 `Level_001` 等稳定名称，避免发布后随意修改 |
| 关卡名称 / DisplayName | 给人阅读的名称，可使用中文 |
| ContentRevision | 内容修订号；已有 DA 的布局发生变化并保存时递增，单纯改名不会触发布局递增 |
| DataVersion | 数据结构版本，目前为 1；工具不提供编辑入口，不是日常关卡修订号 |
| 宽／高 | 工具各限制为 1～64；输入后必须点击“调整地图尺寸”才生效 |
| 地形 | 地板、墙、空洞；只有地板允许放置目标点和占用物 |
| 目标点 | 独立开关，可与玩家或箱子共存 |
| 占用物 | 无、玩家出生点、箱子，单格三选一 |
| BoxId | 箱子内部标识，由工具分配非负且未占用的 ID；日常制作无需填写 |

推荐资产命名 `DA_Level_001`，目录 `/Game/Sokoban/Levels`。这是制作约定，工具并不强制统一前缀或目录。保存新关卡时，如果 ID 为空，会使用资产名填入 ID；已有关卡 ID 为空或 ID 与其他资产重复时不能保存。LevelId 使用 FName，不应依靠大小写差异区分关卡。

当前工具只接受 `DataVersion = 1` 的关卡。遇到其他版本应交由程序处理迁移，不要通过手改版本号强行打开。

## 4. 日常制作步骤

### 4.1 新建或打开

点击“新建关卡”，得到默认 7×5、全地板的草稿。新草稿没有有效出生点、箱子或目标，出现校验问题是正常状态。填写关卡 ID 和名称，按回车或离开输入框提交文本。

修改已有内容时，使用顶部资产选择框打开 DA。打开动作将资产复制到工具草稿中，不会直接改写原资产。工具不会自动修复已有错误数据。

### 4.2 确定尺寸

输入宽度和高度，点击“调整地图尺寸”。调整保留左上角重叠区域；扩展区域填充地板。缩小地图会删除范围外的箱子和目标，出生点被裁掉后需要重新设置。缩小或修复无法显示的网格时会有确认提示。

宽高输入框中的数字只是待应用值。没有点击调整按钮，就没有改变布局，也不会单独作为未保存修改记录。

### 4.3 配置格子

1. 点击中间网格的目标格子。
2. 在右侧选择地形。
3. 若为地板，设置是否为目标点，再选择占用物。
4. 点击“应用到格子”，确认中间布局更新。

设置新的玩家出生点会替代旧出生点。箱子改为“无”即可移除；取消目标点开关即可移除目标。墙和空洞会清除该格的目标及占用物；如果原格存在这些内容，应用前会提示确认。

在箱子格上增加目标，只需保持占用物为“箱子”并勾选目标；不要把“目标”当作另一种占用物。工具会尽量保留原箱子 ID。

### 4.4 校验和修正

点击“校验关卡”。如果右侧有待应用修改，先按弹窗选择应用、丢弃或取消。左侧问题列表可定位相关格子；不对应有效坐标的问题需要按说明修改关卡信息或尺寸。

| 问题类型 | 修正方式 |
|---|---|
| 缺少／重复关卡 ID | 填写项目内唯一标识，检查其他 DA |
| 出生点无效 | 在有效地板格上设置玩家出生点 |
| 箱子或目标缺失、数量不一致 | 保证至少一箱一目标，并使数量相等 |
| 箱子、玩家或目标不在地板上 | 修改地形或重新放置 |
| 坐标越界 | 调整尺寸或移除／重新配置越界对象 |
| 重复占用、重复目标、非法箱子 ID | 修正相应格子；来自直接编辑数组的异常可联系程序检查 |
| 地形数量与尺寸不匹配 | 通过“调整地图尺寸”重建可显示网格，再逐项检查剩余问题 |

校验通过只说明数据结构可以运行。它不检查死锁、玩家到达性、最优解或谜题可解性，交付前仍需人工完成解法。

### 4.5 保存资产

点击“保存资产”。新关卡选择目录和文件名，已有 DA 保存回原资产。新建路径不允许直接覆盖同名资产。

保存允许保留尚未完成的布局，例如暂时没有箱子或目标；工具会提示仍有校验问题。**“草稿已保存”不等于“已经可以试玩或交付”。** 缺失／重复 ID、路径或权限错误等仍可能阻止保存。

如果工具发现原资产在外部被修改，会询问是否覆盖。选择“否”可停止本次保存、保留工具草稿，先核对两边差异；工具没有自动合并功能。

若提示保存未完成，保留当前面板，检查文件只读、版本控制签出、目录权限或保存取消等原因，然后重试。失败处理会还原资产内存字段并保留草稿；新建过程中可能已经产生资产对象，不能假设所有创建操作都被撤销。

### 4.6 接入试玩

1. 确认校验无错误，执行“保存资产”。
2. 打开 `/Game/Sokoban/Levels/DA_SokobanCatalog`，将 DA 加入 Levels 并保存；GameMode 的 Level Catalog 应引用此目录。
3. 打开 `/Game/Sokoban/L_SokobanPlayerGround`。
4. 点击 Play，从主菜单进入选关，选择此 DA 对应条目，验证布局并按预期解法通关。
5. 修改关卡后停止 Play、重新保存并再次 Play；保存动作不会热更新已经开始的对局。

正式模式从目录选关，Startup Level 只在关闭 Enable Frontend 的旧单关调试模式使用，详见[正式流程接入](Frontend.md)。不要忘记将新 DA 加入目录。运行时使用布局副本，玩家移动不会覆盖 DA 中的初始位置。

## 5. 三种“修改状态”与撤销

| 状态 | 数据在哪里 | 如何进入下一步 |
|---|---|---|
| 格子待应用 | 右侧控件的临时选项 | 点击“应用到格子”写入工具草稿 |
| 工具草稿已修改 | 当前面板的编辑文档 | 点击“保存资产”写入 DA 并保存包 |
| 资产已保存 | `.uasset` 文件 | 加入关卡目录，重新 Play 并选关 |

切换格子时，如果有待应用内容，弹窗中的“是”表示应用，“否”表示丢弃待应用选项，“取消”表示留在当前操作。新建、打开其他资产和关闭面板时，还会处理整份草稿是否保存。

工具保留最近 **128 次编辑快照**，使用顶部“撤销编辑／重做编辑”。有格子待应用时，第一次撤销先丢弃这些待应用选项；后续撤销才回退已经提交的编辑。新编辑清除重做分支。工具历史不与场景 Actor 的全局撤销共用，也没有承诺使用 Ctrl+Z 控制该历史。

保存后仍可在当前面板内撤销已提交编辑，撤销会使草稿重新变脏，需要再次保存才影响资产。打开或新建其他文档会清空当前编辑历史。运行时的 Z／Y 是另一套单局历史，不会撤销制作过程。

退出 UE 前，应在工具中主动保存。私有草稿不是场景资产，不能依赖场景“全部保存”或应用退出流程自动保存它；当前也没有崩溃恢复与跨会话草稿持久化。

## 6. 双箱示例：可复现的制作与验收样例

新建 7×5 关卡，使用唯一 ID，例如 `Level_Demo_01`。所有内部格子保持地板，将外围边界逐格设为墙，再按表配置：

| 内容 | 坐标 |
|---|---|
| 墙 | Y=0、Y=4 的所有格子；X=0、X=6 的所有格子 |
| 玩家出生点 | `(2,3)` |
| 箱子 | `(2,2)`、`(4,2)` |
| 目标点 | `(2,1)`、`(4,1)` |

逐格配置后校验、保存并接入 GameMode。待每一步动画完成，依次按 **W、S、D、D、W**，两个 D 分别按下。预期 5 步、2 次推动，最后一个箱子到位并完成动画后出现通关提示。

正式流程中，通关动画结束后显示结算并保存成绩，此时 Z／Y／R 被禁用；点击“重新挑战”恢复初始棋盘。撤销／重做应在未完成关卡前验证。关闭 Enable Frontend 的旧单关调试模式仍允许通关后撤销。这个样例验证制作和接入流程，不作为正式关卡难度设计范本。

## 7. 交付检查表

- [ ] 关卡 ID 唯一，名称清楚；资产文件与相关 GameMode 引用已保存。
- [ ] 编辑器结构校验无错误，没有未处理的待应用修改。
- [ ] 实际 Play 读取的是本次提交的 DA，布局与策划预期一致。
- [ ] 已记录一条可通关的操作序列；验证最后一推后的通关反馈。
- [ ] 已验证撤销、重做、重开，以及撞墙、越界或箱子阻挡时不增加计数。
- [ ] 没有把“结构合法”当作“无死锁”；已人工检查主要路径与难度意图。
- [ ] 版本控制中包含修改的 `.uasset`，没有误提交缓存、测试报告或构建产物。

建议随关卡提交记录以下信息，作为团队交接约定：关卡 ID、资产路径、内容修订号、设计目标、预期解法、已知问题。当前工具不会自动生成这份记录，也不会自动跟踪审批状态。

## 8. 当前工具边界

当前支持单份文档、单格配置、最大 64×64 网格、最近 128 次编辑历史、结构校验和 DA 保存。尚未提供多格批量操作、三维拖放编辑、工具内一键试玩、自动求解、关卡排序管理、多人编辑合并或自动恢复。不要将这些能力作为当前制作流程的前提。
